## О проекте

Прототип демонстрирует:
- 3D-лабиринт, перемещение игрока и сбор пеллет
- Трёх врагов с разными алгоритмами поведения на базе NavMesh
- Полный цикл состояний игры: Старт → Игра → Пауза → Победа / Проигрыш
- Систему сохранений и метапрогрессии (накопленные пеллеты тратятся на способности)
- Сенсорное управление через виртуальный джойстик
- Миникарту через RenderTexture с отдельной камерой и слоями маркеров
- HUD, панели результата, главное меню, звуки и BGM
- Архитектуру на основе MVVM с разделением модели, представлений и логики

## Геймплей

Игрок управляет персонажем в 3D-лабиринте, собирает пеллеты и избегает врагов. Победа — все пеллеты собраны. Поражение — закончились жизни.

Собранные за игру пеллеты добавляются в общий счётчик прогресса, который сохраняется между сессиями. Этот счётчик можно тратить во время игры на две способности:

- **Неуязвимость** — 30 пеллет, длительность 20 секунд, кулдаун 20 секунд
- **Дополнительная жизнь** — 50 пеллет, доступна, пока жизней меньше трёх

## Технологии

- **Unity 6.4 (6000.4.1f1)**
- **URP** (Universal Render Pipeline)
- **NavMesh / NavMeshAgent** — навигация и поиск пути для врагов
- **C#** — основная логика
- **Платформа**: Android (минимальный API уровня 24+)

## Архитектура

Проект построен на **MVVM** с явным разделением на слои:

```
View ──> ViewModel ──> Model
  ▲          │
  └──events──┘
```

- **Model** — чистая логика и данные. Не знает о Unity-сцене и UI. Эмитит события об изменениях.
- **ViewModel** — посредник. Подписывается на события Model, ретранслирует их во View, принимает команды от View и применяет их к Model.
- **View** — `MonoBehaviour`-компоненты. Отображают данные и обрабатывают ввод пользователя. Логику не содержат.

### Ключевые принципы

**Интерфейсы для слабой связности.** Расположены в `Core/Interfaces`:
- `IEnemy` — контракт для врагов (StartChase, StopChase, ResetToSpawn)
- `ICollectible` — контракт для собираемых объектов
- `IPlayerInput` — абстракция над источником ввода (джойстик, тестовый ввод)
- `IGameStateListener` — для компонентов, реагирующих на смену состояний игры

**ООП.** Враги наследуются от абстрактного `EnemyBase`. Базовый класс инкапсулирует общую логику (NavMeshAgent, поиск игрока, базовые состояния), а наследники переопределяют `UpdateBehaviour()` и `GetBehaviourType()` — классическая шаблонная реализация (Template Method).

**Композиция через DI вручную.** `GameBootstrap` — единая точка входа сцены. Здесь создаются модели, viewmodels, и они вкручиваются (`Construct(...)`) в нужные view. Никаких синглтонов поверх Unity для основного gameplay-стека.

### Враги

Все враги — `EnemyBase` + конкретный класс. Используют `NavMeshAgent`.

| Класс | Поведение |
|---|---|
| `DirectChaseEnemy` | Прямое преследование. При попадании игрока в радиус — двигается прямо к нему. |
| `PatrolChaseEnemy` | Патрулирует точки на сцене. При обнаружении игрока в радиусе переключается в режим преследования. После потери игрока возвращается к патрулю. |
| `AmbushEnemy` | Засада: ждёт у спавна. Если игрок подошёл слишком близко — атакует. После погони (по таймеру) возвращается на исходную позицию. |

Тип поведения хранится в `EnemyBehaviourType` (enum), это позволяет View-слою или другим системам различать врагов без `is`/`as`-проверок типов.

### Состояния игры

Перечисление `GameState`: `Start`, `Playing`, `Paused`, `Win`, `Lose`. Смена состояния централизована в `GameModel.ChangeState()`. На событие `OnStateChanged` подписывается `GameHUDView`, который и оркестрирует UI: какие панели показать/скрыть, что делать с `Time.timeScale`, какой звук проиграть.

### Сохранения

`PlayerProgressService` (статический фасад) + `Saver<T>` — типизированная обёртка над `JsonUtility` и записью в `Application.persistentDataPath`. Сохраняем накопленные пеллеты и флаги способностей в `player_progress.json`.

Сохранение происходит:
- При активации способности (списание пеллет)
- В момент Win/Lose (заработок за раунд)

### Миникарта

Реализована через **отдельную ортогональную камеру**, рендерящую в `RenderTexture`, который отображается на UI через `RawImage`. Маркеры реальных объектов выносятся на отдельные слои (`MinimapPlayer`, `MinimapEnemy`, `MinimapWall`, `MinimapPellet`), и миникарте рендерятся только эти слои.

`MinimapMarker.cs` создаёт квад-маркер в рантайме, использует материалы, назначенные через инспектор (это важно для билда APK — `Shader.Find` в рантайме ненадёжен на устройстве, потому что неиспользуемые шейдеры выбрасываются из сборки).


## Установка и запуск

### Требования

- Unity **6.4 (6000.4.1f1)** или совместимая версия
- Android Build Support модуль (для сборки APK)
- Установленный Android SDK и JDK (Unity Hub поставит автоматически)

### Открытие проекта

1. Клонируй репозиторий:
   ```bash
   git clone https://github.com/Twinkiii/pacman-3d.git
   cd <папка-проекта>
   ```
2. Открой Unity Hub → **Add project from disk** → выбери папку проекта.
3. Открой проект указанной версией Unity.
4. Открой сцену `Assets/Scenes/MainMenu.unity` (или сцену с именем главного меню в твоём проекте) и запусти Play.

### Запуск в редакторе

В редакторе работает и виртуальный джойстик, и обычный ввод (если присутствует). Нажми **Play** и проверь логику.

## Сборка APK

1. **File → Build Profiles** → выбрать **Android**, **Switch Platform**.
2. Добавь сцены в Build Settings: меню → игровая сцена.
3. **Player Settings**:
   - Company Name / Product Name — на свой вкус
   - **Minimum API Level** — Android 7.0 (API 24) или выше
   - **Scripting Backend** — IL2CPP
   - **Target Architectures** — ARM64 (обязательно для публикации)
4. **Project Settings → Graphics → Always Included Shaders** — убедись, что `Universal Render Pipeline/Unlit` присутствует (иначе маркеры миникарты не отрисуются на устройстве).
5. **Project Settings → Tags and Layers** — должны быть слои `MinimapPlayer`, `MinimapEnemy`, `MinimapWall`, `MinimapPellet`.
6. **Build** → собери APK.

Готовый APK можно установить на устройство через `adb install` или загрузкой через USB.

## Реализованный функционал

### Основное (по ТЗ)

- 3D-лабиринт с перемещением игрока
- Сбор пеллет, отображение прогресса
- Три типа врагов с разными алгоритмами на NavMesh:
  - Прямое преследование
  - Патрулирование с переключением на преследование
  - Засадное поведение
- Состояния: Старт → Игра → Пауза → Победа / Проигрыш
- UI: счёт, жизни, пеллеты, кнопка паузы, панели результата
- MVVM-архитектура с разделением слоёв
- Использование интерфейсов для контрактов между слоями
- ООП: наследование (`EnemyBase`), полиморфизм (поведение врагов), инкапсуляция (модели)
- Сенсорное управление (виртуальный джойстик)
- Билд для Android

### Бонусы

- Звуки (сбор пеллеты, победа, поражение) и фоновая музыка
- Система сохранений (JSON в `persistentDataPath`)
- Метапрогрессия: накопленные пеллеты тратятся на способности
- Способности «Неуязвимость» и «Дополнительная жизнь» с кулдаунами и стоимостью
- Миникарта на отдельной камере с маркерами объектов
- Главное меню и сцена с игрой
- Целевой FPS 60, отключён vSync для мобильных устройств
